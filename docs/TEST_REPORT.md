## 复现

```bash
scripts/prepare_testdata.sh
```

```bash
docker compose up -d --build
```

```bash
docker compose exec backend multimo testsuite -register
```

`-register` 先登记 `testdata/benchmark/corpus.json` 中的 223 个文件并等待处理完成（首次处理耗时较长，主要是约 300 个关键帧的 VLM 分析和 2361 个底图切片的向量化），然后运行评测。语料已处理过时去掉 `-register`，或调用 `POST /api/v1/testsuite/run`。

问答结果每次运行会有小幅波动，因为 VLM 回答和 Decision 打分不是完全确定的：P5 期间 4 次完整运行分别为 40、41、41、42 题正确（期间有代码改动，见调优记录），其中 qa50 在第一次运行中判错，单独重问时回答正确。检索结果在代码不变时是稳定的。

### 目标识别：准确率 76.8%、漏检率 33.9%，未达标

VisDrone2019-DET 验证集 100 张图，共 3093 个可见目标（面积 ≥ 600 像素且非重度遮挡），平均每张 31 个。

| 口径 | TP | FP | FN | 准确率 | 漏检率 |
| :--- | ---: | ---: | ---: | ---: | ---: |
| 类别一致（主指标） | 2046 | 619 | 1047 | 76.8% | 33.9% |
| 同大类（车辆 / 人 / 两轮车 / 三轮车） | 2238 | 433 | 855 | 83.8% | 27.6% |
| 类别一致，不排除与不可见目标重合的预测 | | | | 50.3% | |

| 类别 | 可见标注 | 准确率 | 召回率 |
| :--- | ---: | ---: | ---: |
| car | 1518 | 87.2% | 79.7% |
| pedestrian | 414 | 68.3% | 72.9% |
| motor | 347 | 69.7% | 53.6% |
| people | 229 | 56.0% | 42.8% |
| van | 216 | 74.7% | 50.5% |
| tricycle / awning-tricycle | 166 | 50.0% / 52.0% | 28.7% / 20.0% |
| bicycle | 88 | 46.4% | 36.4% |
| truck / bus | 115 | 74.6% / 83.3% | 55.3% / 66.7% |

原因分析：

- 占目标一半的小汽车已接近要求（准确率 87.2%、召回率 79.7%），差距集中在小而密的类别：行人和骑车人（pedestrian / people 的区分本身也容易混淆）、摩托车、自行车、三轮车。这些目标在 1280 px 的画面里通常只有十几到几十个像素宽。
- 不与可见标注匹配的约 2020 个预测中，有 1401 个框中了被标注为不可见的目标（面积小于 600 像素或重度遮挡）或落在忽略区域内，按 VisDrone/COCO 惯例不计入误报；不这样处理时准确率只有 50.3%。
- VLM 一次输出几十个框时，框的位置精度不足以稳定达到 IoU 0.5，这是漏检的主要来源，单靠提示词无法解决。

做过的尝试见“调优记录”中的分块检测：召回率提高 8 个百分点，但准确率同步下降，漏检率仍在 30% 左右，没有采用。要达到准确率 85%、漏检 5% 的要求，需要接入在 VisDrone 类数据上训练过的专用检测模型做框，VLM 负责描述、语义和复核；这是后续工作。

### 空间对齐：DJI 飞行记录路径通过；无元数据的视觉定位中位误差 108 m，未达标

**有元数据**：DJI 视频按文件名时间与飞行记录对齐（自动识别出 UTC-8 时区偏移），51 个关键帧全部由飞行记录插值定位，存储坐标与独立插值结果一致（最大偏差 0.00 m）。这里的真值就是飞行记录本身，所以只作为流程验证。

**无元数据**：UAV-VisLoc 01 区 82 张照片，不提供 GPS，只给拍摄时间和同一区域的卫星底图（0.3 m 分辨率 GeoTIFF）。系统把照片与底图切片做图像向量匹配，按时间顺序做航迹平滑，再在选中位置附近做局部细化。

| 已定位 | 中位误差 | 平均误差 | P90 | <100 m | <250 m |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 82/82 | 108 m | 277 m | 770 m | 48.8% | 63.4% |

原因分析：前 30 个候选中有一个在 100 m 内的照片占 81.7%，但最终选中的只有 48.8%。瓶颈在于从候选中选对位置：照片和卫星图拍摄于不同年份和季节，农田、水面的外观差别大，图像向量的相似度区分不开相邻的相似地块。让 VLM 在候选中挑选、用 SIFT/ORB 做几何校验都试过，都没有改善（见调优记录）。

### 检索：准确率 86.8%、查全率 84.6%，达标

50 条 query，按素材聚合。准确率 = 前 10 名中的相关数 ÷ min(10, 相关总数)；查全率 = 前 max(10, 相关总数) 名中的相关数 ÷ 相关总数。

| :--- | ---: | ---: | ---: |
| 文档 | 12 | 100% | 100% |
| 视频 | 6 | 100% | 100% |
| 时间 | 2 | 100% | 100% |
| 遥感影像目标 | 10 | 84.7% | 84.8% |
| 空间（坐标、半径、经纬度范围、地名） | 8 | 80.8% | 79.9% |

剩余误差：目标类 query 的相关集合由人工标注计数决定（如“摩托车 10 辆以上”），系统依据 VLM 的计数，受上面目标识别召回率的限制；空间类 query 受视觉定位误差限制（用真值坐标时这 6 条 VisLoc 空间 query 全部满分）。

## 评测方法的修正

评测代码本身也有过几处修正，结果以修正后为准：

- **UAVDT 忽略区域**：UAVDT 为每段视频提供 `*_gt_ignore.txt`，标出车辆未标注的区域（M1004 第 1 帧有 3 块，占画面大半）。按数据集协议，落在这些区域的检测不计；原来没有读取，导致 M1004 的 23 个检测被算作误报。关键帧一致性 58.8% → 59.7%。
- **按类别的准确率和召回率**：原来按类别匹配时把其他类别的标注也算作漏检，召回率出现负数。改为每个类别的预测只与该类标注匹配。只影响明细表，主指标不变。
- **问答评分规则**：把 Decision 的评分说明写明确：只评判问题实际询问的内容；参考答案中标为“约”的人工计数允许 ±25%；超出问题范围的细节只有与参考答案矛盾时才扣分。实测对结果没有影响（同一批回答前后都是部分正确的仍是部分正确）。
- **坐标解析**：坐标题除“北纬/东经”写法外，也识别“纬度 33.7、经度 -118.3”这种带符号的写法。
- **检索准确率定义**：按要求定为前 10 名中的相关数 ÷ min(10, 相关总数)，即相关结果只有 1~2 个时，出现在前 10 名就算 100%。传统的 P@10 一并列出（0.356）。
